**贯穿作品 · 小北的网站**

小北的网站已经很像样了：主页排得整整齐齐，待办清单能用，天气能查，还有第 17 章新加的留言板。可是有一个问题一直绕不过去——这个网站只有在他自己的电脑上能打开。他想把网址发给同学看，同学点开却是一片空白，因为文件还躺在他电脑的硬盘里，别人根本够不着。

这一章就是全书的最后一步：把网站从"自己电脑上的文件"，变成"全世界任何人输入网址就能打开的网站"。小北会用两种方式各发一遍：静态版发到 GitHub Pages，React 版发到 Vercel。做完这一章，你的网站也会拿到两个能发给任何人的网址。

这一步有个专门的词，叫**部署**。别被它吓住，说白了就是"把网站文件放到一台一直开机的电脑上，让别人能访问"。下面我们一步步来。

## 18.1 部署是什么：从本地文件到全世界可访问

![部署流程：本地文件推到 GitHub，再由 Pages 或 Vercel 发给全世界](../images/fig-ch18-deploy.svg)

先用一个比方把概念说清。你在自己电脑上写的网页，就像写在本子上的日记——写得再好，也只有翻开本子的人能看到。部署，就是把这本日记贴到学校的公告栏上：谁路过，谁就能看。

具体到网站，公告栏就是**服务器**。服务器你可以理解成"一台放在机房里、一天 24 小时开机、专门用来存放网站并回应访问的电脑"。有人在浏览器里输入你的网址，浏览器就跑去这台服务器上取文件，取回来渲染成你看到的页面——这正是第 1 章讲过的"一次访问的完整旅程"，只不过这次主角换成了你自己的网站。

那你需要自己买一台服务器吗？不需要。有很多平台愿意替你保管文件并对外提供访问，这种服务叫**托管**。你把文件交给平台，平台负责让全世界都能打开，还顺带送你一个网址。本章用的 GitHub Pages 和 Vercel，都是免费的托管平台。

为什么它们愿意免费？关键在你的网站是**静态网站**。静态网站的意思是：网站由 HTML、CSS、JavaScript 这些现成文件组成，浏览器拿到手就能直接显示，服务器要做的只是"把文件递出去"，不费什么力气。相对地，有些网站每次访问都要在服务器上现算一遍数据（比如每个人看到的购物车都不一样），那种网站对服务器要求高得多，往往要花钱。你的个人网站递文件就够了，所以可以免费托管——这也是个人作品集特别适合拿来练部署的原因。

部署成功后，你的网址大概长这样：

```text
https://你的用户名.github.io/仓库名/
https://项目名.vercel.app/
```

这两个网址就是你这一章的"毕业证书"。拿到它们，就说明你真的把网站发出去了。

## 18.2 GitHub Pages：免费发布你的网站

GitHub Pages 是 GitHub 自带的免费托管服务：第 12 章你已经把代码推到了 GitHub 仓库，离发布只差打开一个开关。发布的将是静态版，也就是纯 HTML、CSS、JavaScript 写的那些页面（第 14 章 React 化之前的版本）。

发布前先确认一件事：静态版的 `index.html` 在仓库根目录里，也就是打开仓库首页就能直接看到它。GitHub Pages 默认从这里找首页，找不到就会出问题（本章最后的翻车现场讲的就是这件事）。

确认好之后，跟着做：

1. 打开浏览器，进入你的 GitHub 仓库页面（就是第 12 章推代码的那个仓库）。
2. 点仓库上方菜单里的 **Settings**（设置）。看不到的话，先确认你登录的是自己的账号。
3. 在左侧菜单里找到 **Pages**，点进去。
4. 在 "Build and deployment"（构建与部署）区域，Source（来源）选 **Deploy from a branch**（从分支部署）。
5. 下面的 Branch（分支）选 **main**，文件夹选 **/(root)**，点 **Save**（保存）。
6. 等一两分钟，刷新这个页面。看到顶部出现一行提示 "Your site is live at https://…"，就说明发布成功了。

点开那行提示里的网址验证一下：能看到小北的主页、样式正常加载、点几个链接都能跳转，就是真的上线了。网址的构成也顺便认识一下：`https://你的用户名.github.io/仓库名/`——用户名和仓库名换成你自己的，就是你的专属地址。

上线之后更新网站也很简单：改完代码，照第 12 章的老三样提交并推送，GitHub Pages 会自动重新发布，你什么都不用再点。

```bash
git add .
git commit -m "更新主页介绍"
git push
```

推送完等一分钟左右，刷新你的网址，应该就能看到新版本。如果没变，别急，多半是浏览器缓存，按 `Ctrl + F5`（Mac 是 `Command + Shift + R`）强制刷新一次。

## 18.3 Vercel：现代前端的部署方式

静态版发出去了，但第 14 章的 React 版还没地方放。React 的源代码浏览器不能直接读，必须先"打包"成普通的 HTML、CSS、JavaScript 文件才能发布。本地打包的命令你其实见过：

```bash
npm run build
```

（运行这条命令前，先确认第 2 章装好的 Node.js 还在：终端里输入 `node -v` 能显示版本号就行。）打包结果会放在 `dist` 文件夹里。问题是：每次改完代码都要自己打包、自己上传，太麻烦了。**Vercel** 这类现代部署平台就是来替你干这件事的：你只管把源代码推到 GitHub，它自动打包、自动发布。

跟着做一遍：

1. 打开 `vercel.com`，点 **Sign Up**，选 **Continue with GitHub**，用你的 GitHub 账号登录并授权。这一步是让 Vercel 能读取你的仓库。
2. 登录后进入控制台，点 **Add New** → **Project**（新建项目）。
3. 在 "Import Git Repository"（导入 Git 仓库）列表里找到小北网站的仓库，点 **Import**。如果 React 项目在仓库的某个子文件夹里，在导入页面把 **Root Directory**（根目录）指到那个文件夹。
4. 接下来是配置页。Vercel 会自动认出这是 Vite 项目，打包命令和输出目录都替你填好了，**什么都不用改**，直接点 **Deploy**（部署）。
5. 等待一分钟左右，页面开始滚动构建日志——这是它在云端替你运行 `npm run build`。看到撒花动画和 "Congratulations" 字样，就是部署成功。
6. 成功页面上会显示你的网址，形如 `https://项目名.vercel.app/`。点开检查：React 版主页能打开、待办清单能加能删，就全对了。

Vercel 最舒服的地方是**自动部署**：从此你每次 `git push`，它都会自动重新打包、发布新版本。你只管写代码，发布这件事从流程里消失了——这正是现在真实项目里的工作方式，GitHub Pages 是手动挡，Vercel 是自动挡，两个都体验一遍，你就都懂了。

## 18.4 整理作品集：让网站替你说话

网站能打开，只是"上线"；让来看的人觉得"这人不错"，才叫"作品集"。小北的网站以后要放简历、给实习单位看，所以上线前要认真整理一遍门面。

主页上应该有这四样东西：

- **一句话介绍**：你是谁、在学什么。比如"小北，大一在读，喜欢摄影，正在学习做网站"。别写"欢迎来到我的主页"这种谁都能写的话。
- **作品列表**：你做过的东西，每个都要能点开。小北的作品就是这个网站里的待办清单、天气应用、留言板——正好都能在线体验，这比任何描述都有说服力。
- **技能清单**：老老实实写学过的：HTML、CSS、JavaScript、React、Tailwind、Git，再加一句"会用 AI 编程助手协作开发"。学到哪写到哪，别夸大。
- **联系方式**：一个真的能收到信的邮箱。注意，只放邮箱这类公开联系方式，不要把家庭住址、电话号码这类私人信息挂到全世界都能看的页面上。

最后，照着这份**上线前检查清单**逐项打勾，全过一遍再把网址发出去：

- [ ] 网页标题是"小北的空间"，不是浏览器默认的那串字
- [ ] 主页上的每个链接都亲手点过，都能打开
- [ ] 用手机打开网址看一遍，排版没有错位、字不会小到看不清
- [ ] 所有图片都能正常加载，没有裂开的图
- [ ] 待办清单、天气、留言板都实际用了一遍，功能正常
- [ ] 页面上没有"测试""随便写写"这类残留文字
- [ ] 在同学的电脑或手机上打开过一次（换台设备最能发现问题）

**上线不是把文件扔出去就完事，而是把"给别人看的版本"认真收拾体面**。这份清单以后每发布一个新作品，都可以拿出来再用一遍。

## 18.5 下一步学习地图：前端之后往哪走

走到这里，先把你已经会的东西数一遍：你能写 HTML 搭结构、用 CSS 做样式和布局、用 JavaScript 让页面动起来、用 Git 管理版本、用 React 和 Tailwind 写现代前端、会指挥 AI 助手帮你干活，还能把网站部署到全世界——这已经是一个完整的前端入门闭环了，很多人的学习就卡在前面某一环，你是走完的。

接下来往哪走？给你四个方向，按兴趣挑，不用全学：

- **TypeScript**：在 JavaScript 上加"类型标注"，写大一点的项目时能提前拦住很多低级错误。前端岗位几乎都要求它，是性价比最高的一步。
- **后端与数据库**：到目前为止，你的网站数据只存在访客自己的浏览器里（还记得 localStorage 吗）。学一点后端——比如用 Node.js 写简单的服务器、把数据存进数据库——你的网站就能有注册登录、能让不同的人看到同一份留言板，从"页面"长成真正的"应用"。下一章（第 19 章）我们就动手把这件事做出来。
- **小程序**：如果以后想给国内用户做产品，微信小程序是个好去处。它的写法和你学的 HTML、CSS、JavaScript 是亲戚，上手会比想象中快。
- **继续用 AI 助手做真实项目**：工具会一直变，但"把想法说清楚、拆成小步、验收结果"的方法不会过时。给社团做一个报名页、给家里的小店做一个展示站——真实需求是最好的老师，做完一个，水平就涨一截。

最后留一条节奏上的建议：**每月给自己定一个小作品，做完就部署上线**。学编程最怕"一直学、从不发"，而你现在已经掌握了从写代码到发网址的完整链路，用起来，它就不会生锈。

这本书到这里就结束了，但小北的网站还挂在网上，你的也是。从一行 `<!DOCTYPE html>` 开始，到拥有一个全世界都能打开的网址——这条路你已经完整走过一遍了。接下来，就是你自己选方向、自己往前走的时候了。祝你玩得开心，做得漂亮。

## 本章要点

- 部署就是把网站文件放到一直开机的服务器上，让任何人输入网址就能访问；替你保管文件的服务叫托管。
- 静态网站只需要服务器"递文件"，不费力，所以 GitHub Pages、Vercel 愿意免费托管。
- GitHub Pages：在仓库 Settings → Pages 里选 main 分支和根目录，保存后等一两分钟即可上线；之后每次 push 自动更新。
- Vercel：导入 GitHub 仓库后自动打包、自动发布 React 项目；每次 push 都会触发自动部署。
- 作品集主页要有一句话介绍、能点开的作品、如实的技能清单和可用的联系方式。
- 上线前逐项过检查清单：标题、链接、手机效果、图片、功能、残留文字、换设备验证。
- 前端之后的方向：TypeScript、后端与数据库、小程序、用 AI 助手做真实项目；保持每月一个小作品并上线的节奏。

## 动手 Kata

1. **发布静态版**：按 18.2 的步骤给第 12 章的仓库打开 GitHub Pages。做完应该看到：`https://你的用户名.github.io/仓库名/` 能打开，样式和在本地时一致。
2. **发布 React 版**：按 18.3 的步骤把仓库导入 Vercel。做完应该看到：`https://项目名.vercel.app/` 能打开 React 版主页，待办清单能正常添加和删除。
3. **体验自动部署**：随便改主页上的一句话（比如把介绍里的词换一个），提交并 `git push`，然后什么都别点，等一两分钟刷新两个网址。做完应该看到：两个网址都变成了新版本——这就是自动部署。
4. **当第一个访客**：把你的网址发给一位朋友或同学，请对方在自己的手机上打开，并把第一印象和发现的问题发给你。做完应该拿到：至少一条来自真实访客的反馈，并把它记下来留着以后改。

## 翻车现场

小北第一次开 GitHub Pages，设置全点对了，保存完兴冲冲打开网址，结果页面只有一行大字：**404**，下面写着 "There isn't a GitHub Pages site here."。他对着设置看了三遍，分支选的是 main，文件夹选的是根目录，没错啊？

问题出在文件的位置。整理项目时，他把所有网页文件都收进了一个叫 `website` 的文件夹，仓库首页点开先看到的是文件夹，`index.html` 躲在文件夹里面。而 GitHub Pages 在根目录找首页，找了一圈没找到 `index.html`，就只能回一个 404。**Pages 的 404，十有八九是它没在你说的位置找到 index.html。**

改法很直接：把 `website` 文件夹里的文件全部移到仓库根目录（让打开仓库首页就能直接看到 `index.html`），提交、推送，等一分钟再刷新 Pages 设置页，网址就活过来了。

顺带记住一个孪生小坑：改完代码忘了 `git push`，线上就还是旧版本——自动部署再聪明，也部署不了还没上传的代码。发现"线上怎么没变"时，先检查自己推没推，再怀疑平台。
