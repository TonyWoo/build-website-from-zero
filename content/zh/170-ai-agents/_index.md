**贯穿作品 · 小北的网站**

上一章，小北请 DeepSeek 当陪练，给主页挑出了 3 个问题，再自己动手一个个改好。这一章他想给「小北的空间」添一个新页面：**留言板**——访客能写下留言，还能看到别人留的话。别小看这个页面：要新建文件、要改主页的导航、还要写 JavaScript 把留言存下来，是块不小的活。

这次小北想换个玩法：**请一个 AI 代理来动手写，自己站在旁边当监工**——布置任务、盯着它干活、最后亲自验收。这一章你会跟着他认识两个能"动手"的 AI 工具：DeepSeek Harness 和腾讯 WorkBuddy。先把丑话说在前面：代理再能干，方向盘也得握在你手里。这一章真正要学的不是让 AI 写多少代码，而是怎么指挥它、怎么验收它、怎么防着它把东西改坏。

## 17.1 从"问答"到"代理"：AI 开始自己动手

先把第 16 章的陪练和这一章的代理分清楚。

**陪练只动嘴**。你问它答：讲概念、读代码、帮你看报错。它给的所有东西都是"建议"，代码是你一个字一个字敲的，文件是你自己建的，它碰不到你的电脑。

**代理能动手**。你给它一个任务，它会自己拆开步骤：打开哪个文件、哪几行删掉、哪几行补上、再跑一条命令看看对不对——这些动作真实地发生在你的电脑上。业内把这种能自己动手干活的 AI 叫做 Agent（智能体），这一章你会经常见到这个词，记住它就是"会动手的 AI"。

打个比方：陪练是坐在副驾驶的教练，只动口不动手；代理是你雇来的施工队，你交代"把这面墙刷成蓝色"，它自己买漆、搬梯子、开刷。

还有一个区别也要心里有数：陪练的回答是"一次性"的，它说完就完了，你不采纳，什么都不会发生；代理是"连续干活"的，它做完第一步会接着做第二步，第一步理解偏了，后面会一步比一步偏得远。所以用代理讲究**一步一回头**：每完成一小步，你先检查，没问题再放它走下一步。这个习惯，17.3 里会变成具体的操作流程。

**能力越大，越要盯紧**。教练说错一句话，你顶多听错一个概念；施工队理解错了，可是真会把墙刷错颜色的。所以用代理有三条规矩，贯穿这一整章：任务说清楚、过程盯着看、动手前先留后路。后路是什么？就是第 12 章学的 Git——动工之前先存个档，改坏了能退回去。接下来几节，我们一条一条落到实处。

## 17.2 DeepSeek Harness 上手：它是什么、怎么打开、选工作区

DeepSeek Harness（简称 dsh）是 DeepSeek 官方推出的开源 Agent 运行环境。"harness"原意是给马套的挽具，你可以把它理解成**给 AI 模型套上的一套干活装备**：有了它，AI 不再只是聊天，而是能读写文件、执行命令、调用各种工具。它最大的特点是"一切皆插件"——工具、界面都能靠插件扩展（底层是一个叫 Cordis 的框架），甚至能用对话让它帮你现做一个插件。这种"核心 + 插件"的设计，你在第 13 章的组件思维里已经见过类似的思路了。

打开它有两种方式，任选其一：

**方式一：桌面端**。去 DeepSeek 官方页面下载安装包：Mac 用 Apple 芯片版，Windows 用 64 位版，下载后按提示安装，打开就能用。

**方式二：Web UI（在浏览器里打开**）。前提是电脑装了 Node.js——第 2 章你已经装过，但这里要求版本在 22.19 或更高。先打开终端检查一下：

```bash
node -v
```

版本号够了，就在终端里进到你想让它工作的文件夹，运行这一条命令：

```bash
npx @deepseek-ai/dsh web
```

稍等片刻，浏览器会自动打开它的界面（默认地址是 127.0.0.1:3080）。这个地址只在你自己电脑上有效，别人打不开，放心用。版本号不够的话，去 Node.js 官网重新装一个新版，再回来运行命令。

第一次打开，先做两件事：

1. **填 API Key**。进设置页面，把你的 DeepSeek API Key 填进去（Key 是调用模型的"钥匙"，在 DeepSeek 开放平台申请；Harness 也支持填其他厂商的接口）。记住：Key 相当于密码，不要发到聊天里、不要截图给别人看。
2. **选工作区**。告诉它"只在这个文件夹里干活"，小北选的是自己的网站项目文件夹。**这一步是本章最重要的一步**：工作区选多大，它的手就能伸多远。只选项目文件夹，电脑上其他地方它碰不到。

模式方面简单认识一下：**标准模式**是完整的编程代理，能读文件、改文件、跑命令、搜代码、做计划，还能派"子代理"分头干活，新手用它就够了；另外还有极简模式、Code 模式和能自制插件的创造模式，先不用管。

最后提醒一句：Harness 目前还在**开发者预览**阶段，官方明说后续可能会有大的变动。所以你打开的界面和书里写的不完全一样，是正常现象；对不上的地方，去官方文档站 deepseek-harness.github.io 查最新用法。

## 17.3 用 Harness 编程：拆任务、看它干活、验收与回滚

小北给留言板定的开工流程很值得你原样抄走，一共五步。

**第一步：先存档，再开工**。打开终端，进到项目文件夹，把网站现状存进 Git：

```bash
git add .
git commit -m "加留言板之前存档"
```

这一步相当于动工前给网站拍张全景照：代理接下来不管怎么改，你手里都有一个完好的版本能退回去。

**第二步：任务拆小，一次只派一件**。千万别一口气说"帮我做一个完整的留言板"。小北分了三轮派活，每一轮都说清了文件和完成标准：

1. "在项目里新建 guestbook.html，照着 index.html 的样子放上页头和导航，中间先只放一个标题'留言板'和一句说明。先做这一步。"
2. "给留言板加表单：昵称输入框、留言输入框和提交按钮。再写 JavaScript：点提交后，把留言追加显示在页面下方，留言数据存进 localStorage，刷新不能丢。"
3. "在 index.html 的导航里加一个'留言板'链接，指向 guestbook.html。只加这一行，不要动其他任何地方。"

每派一轮，等它做完、你验收通过，再派下一轮。**步子越小，它越不容易跑偏，你越容易发现问题。**

**第三步：盯着它干活**。代理动手时，界面会列出它读了什么文件、改了什么地方。你重点看两样：改动的文件是不是都在你预料之内；改的内容是不是你想要的。看不懂的改动，当场问它"这一段为什么这么改"。它要是打算动你没提过的文件，先喊停——这和监工看到施工队在拆一面没说要拆的墙，是一个道理。

**第四步：自己跑一遍验收**。它说"做完了"不算数，你亲自打开页面点一遍：留言能不能提交、刷新之后还在不在、从主页点"留言板"能不能跳过去。验收标准最好提前写进派活的话里（比如上面那句"刷新不能丢"），做到没做到，一试便知。

**第五步：改坏了，用 Git 回滚救回来**。小北的第三轮就出了岔子：代理加链接时顺手"优化"了一下导航的样式，主页排版乱了。他一点不慌，先看清改动范围，再把改坏的文件恢复：

```bash
git status
git restore index.html style.css
```

`git status` 是第 12 章的老朋友，它会列出哪些文件被改过；`git restore` 把指定文件恢复成上次存档的样子。前两轮做好的 guestbook.html 是新文件、不在恢复名单里，成果完好无损。恢复之后，小北把任务说得更窄——"只加一行链接，不碰样式"，重派一次，顺利通过。

**记住：代理改坏东西不可怕，没有存档才可怕**。全部验收通过后，再存一次档，把成果钉进历史里：

```bash
git add .
git commit -m "留言板完成"
```

## 17.4 Harness 不只写代码：文档与表格也能干

别被"编程代理"四个字骗了，Harness 的工作区里不只有代码。换上不同的插件和任务，它处理日常文档活同样顺手。小北试过三件：

- **整理文件**。他的"下载"文件夹里几十张照片、课件、文档混成一团。他先新建了一个测试文件夹，把文件复制一份放进去（注意这个动作：**先在副本上练手，不直接对着原件**），把工作区切过去，让 Harness 按类型分好子文件夹，再列一张清单出来。几分钟，文件夹清清爽爽。
- **处理表格**。社团报名表是个 Excel 文件，几十行姓名、电话、报名项目混着填。他让 Harness 读这张表，按项目分组、统计人数，生成一张干净的新表。原来自己筛选复制要小半节课，这次他只花了最后检查一遍数字的时间。
- **写文档**。课程作业要交一份说明文档，他把提纲和素材交给 Harness，让它先写一版初稿，自己再补细节、改语气。从零写初稿是最痛苦的，有个草稿打底，速度完全不一样。
- **查资料**。写课程论文要先摸清一个主题，他让 Harness 帮忙搜集资料，并且特别交代"每条信息标出来源"，最后汇成一份带出处的摘要，他再顺着出处逐个核对。记住这个小要求——标来源——AI 给的资料不能直接信，能追溯到出处，你才验得了真假。

这一节想让你记住一句话：**代理的价值，是把重复、琐碎、步骤明确的活外包出去，你留下来做判断和检查**。不管派的是代码还是文档，流程都是同一套：说清要求、限定范围、检查结果。

## 17.5 WorkBuddy：办公场景的 AI 同事

如果说 Harness 像一间偏开发的车间，WorkBuddy 更像一位坐在你旁边的办公同事。它是腾讯云 CodeBuddy 团队在 2026 年 3 月推出的产品，定位是"全场景职场 AI 智能体"，和编程工具 CodeBuddy 是同一套智能体架构，只是它主攻办公场景。用法和 Harness 类似：桌面应用打开，用一句话交代任务，它自己拆步骤、读取你的本地文件、动手完成。

它最拿手的是办公文档：生成和编辑 Word、Excel、PPT、PDF，把一堆散文件批量整理成表格和报告。对学生来说，课程报告、社团材料、实习申请，都可以找它搭把手。

它也不是完全不能编程。WorkBuddy 可以打开查看、编辑 HTML、Markdown 文件，界面是左边文件、右边对话的"人机双写"：你选中一段文字让它改，它就改那一段，改动还会标出来等你确认。对国内学生还有一个很实际的好处：**国内可以直接下载使用，不用折腾网络**；它还能连上微信、企业微信、QQ 等工具，配置好之后，你在外面用手机发一条消息，就能让宿舍里的电脑帮你把任务跑起来。

隐私方面按官方说法，它只读取你主动打开或添加的文件，不会自己满硬盘翻找；查看和编辑文件本身不消耗积分，调用 AI 能力时按任务计费，具体价格以官方页面为准。

小北用它办成的一件事，正好接上本章的贯穿作品：这学期他的学习笔记散落在十几个文件里，有 Markdown、有随手记的文本，标题层级各写各的。他在 WorkBuddy 里把这些笔记文件逐个打开——**只打开笔记，其他文件不碰**——让它按章节归类、统一标题层级、补一份目录，最后整理成一篇排版整齐的网页文档，挂到了自己的网站上。这件事要是纯手工做，光统一格式就得搭进一个晚上；小北最后花的时间，主要是通读一遍检查有没有归错类。**检查的时间省不掉，那正是你该花时间的地方。**

## 17.6 两个工具怎么选：安全常识收尾

分工其实很好判断，看任务的主场在哪：

- **写代码、改网站是主场，用 Harness**。它就是冲着编程来的：能读写项目文件、能跑命令、能和 Git 配合，进了项目文件夹就像进了车间。
- **办公文档、表格报告、整理资料是主场，用 WorkBuddy**。Word、PPT、Excel 是它的拿手戏，还能顺手帮你改改网页和 Markdown。
- 两个都装着也没问题。很多人的日常就是七分办公、三分代码，按任务换工具，就像写代码开 VS Code、看文档开浏览器一样自然。

还有个笨办法：看它接下来要动的是什么文件。要动的是项目里的代码文件、要跑命令，进 Harness；要动的是 Word、Excel、PPT 和一堆待整理的资料，开 WorkBuddy。工具会一直更新换代，功能细节以官方文档为准，但这个判断方法不会过时。

最后一段是安全常识，请当成规矩记下来：

1. **只从官方渠道下载**。Harness 去 DeepSeek 官方页面或官方 GitHub 仓库，WorkBuddy 去腾讯官方页面。这类工具能读写你的文件、执行命令，来路不明的安装包坚决不装——那等于把家门钥匙交给陌生人。
2. **只授权该看的文件夹**。工作区选项目文件夹就好，别图省事选整个硬盘。下一节翻车现场里，小北就栽在这上面。
3. **重要操作前先存档**。让代理动代码之前，先 Git 存档；让它整理重要文件之前，先复制一份，或者先拿不重要的测试文件夹练一轮。
4. **结果永远自己验收**。代理说"完成了"，你打开看一遍、点一遍、核对一遍，再算数。

## 本章要点

- 陪练只动嘴给建议，代理能动手：读写文件、执行命令；能力越大，越要有人盯着。
- DeepSeek Harness（dsh）是 DeepSeek 官方的开源 Agent 运行环境，"一切皆插件"；桌面端打开，或用 `npx @deepseek-ai/dsh web` 打开 Web UI。
- 打开 Harness 先做两件事：在设置里填好 API Key，选好工作区——只授权项目文件夹。
- 用代理的固定流程：先 commit 存档、任务拆成小步、盯着它改了哪些文件、自己跑一遍验收、满意了再 commit。
- 代理改坏了不慌：`git status` 看改动，`git restore` 把文件恢复到存档版本，前提是开工前存过档。
- Harness 不只写代码，整理文件、处理表格、写文档初稿都能派；WorkBuddy 是腾讯的职场智能体，办公文档是强项，也能改 HTML 和 Markdown，国内可直接使用。
- 安全规矩：官方渠道下载、只授权该看的文件夹、重要操作前先存档、结果永远自己验收。

## 动手 Kata

1. **打开 Harness，只看不动手**。用桌面端或 Web UI 打开 Harness，填好 API Key，把你前面章节做的网站项目文件夹设为工作区，然后只派一个"只读"任务："读一下这个项目，给我讲讲每个文件是干什么的。"做完应该看到：它说得清你的项目结构，而且一个文件都没被改动（可以用 `git status` 验证，应该没有任何改动）。
2. **派第一个小活并存档**。先运行 `git add .` 和 `git commit` 存档，再让 Harness 给主页加一行页脚文字（比如版权信息），盯着它改完，在浏览器里打开主页验收，最后再 commit 一次。做完应该看到：页脚出现新文字，Git 历史里多了开工前、完工后两条记录。
3. **亲手试一次回滚**。故意让 Harness 把主页背景换成一个扎眼的颜色，先别急着骂它——在终端运行 `git restore` 把样式文件恢复。做完应该看到：页面变回原来的样子，你亲手验证了"保险"真的管用。
4. **用 WorkBuddy 整理一份文档**。找一份你自己写得比较乱的笔记（没有的话新建一个测试文件，内容随便写几段），先复制一份留底，再用 WorkBuddy 打开原件，让它统一标题、补上目录。做完应该看到：一份排版整齐的文档，而你的备份文件还完好无损。
5. **给代理派一件非编程的活**。新建一个测试文件夹，随便放进去几个不同类型的文件，让 Harness 按类型分类整理，再生成一份文件清单。做完应该看到：文件分门别类放好，清单和文件夹里的实际文件一一对得上。

## 翻车现场

这一节讲的，是小北**第一次**用 Harness 时的样子——那时候他还没总结出 17.3 的流程。

那天他刚装好 Harness，兴奋得很，工作区随手选了整个用户主目录（想着"反正它什么都能看，省事"），也没想起来 Git 存档，张口就是一句大的："帮我把网站整体优化一下，顺便把文件夹整理整理。"代理非常"能干"：它把主页的样式文件换了个名字挪了位置，又觉得几个文件的命名不规范，挨个改了名，还顺手"整理"了同目录下其他文件夹里的文件。

结果：网站打开一片素颜——样式文件改名之后，主页找不到它了；照片墙的图片路径也对不上，裂了一片。小北对着一堆改过名字的文件，根本说不清哪个是哪个。万幸的是，第 12 章他把网站推上过 GitHub，云端还躺着一份完好的代码。他把云端版本重新拉下来对着恢复，照片和其他文件逐个改回名字，忙活了整整一个晚上，总算没丢东西——丢的只是一个晚上的时间，和一脑门子汗。

复盘一下，这次翻车没有一条是代理的"错"：**任务太大**（"整体优化"等于没标准，它只能自由发挥）、**授权太宽**（工作区选了整个主目录，它的手自然伸到了不相干的文件夹）、**没留后路**（开工前没存档，改坏了只能靠云端备份抢救）。本章那三条规矩——任务拆小、只授权项目文件夹、先 commit 再开工——就是从这个晚上长出来的。你第一次用代理时，照着 17.3 的五步走，就不用再交这笔学费了。
