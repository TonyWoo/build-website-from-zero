**贯穿作品 · 小北的网站**

第 10 章给主页加上待办清单以后，小北越用越上头，又接连加了几个小功能：可以只看"还没做完"的、每条待办能改文字、顶部还显示"还剩几件事"。结果那个 JS 文件越写越长，改一个小地方经常牵连出三处毛病——数组里的数据明明删了，页面上还留着；计数改对了，列表又忘了跟着变。他对着满屏的 `querySelector` 和 `addEventListener` 叹气："怎么感觉我一直在给页面打补丁？"

学长听完笑了："不是你 JS 没学好，是页面长大了，老办法不够用了。该学 React 了。"

React 是目前真实项目里用得最多的前端框架（框架，你可以理解成一套现成的"写页面的方法论加工具箱"）。这一章我们先不碰小北的主页，先把 React 的思考方式弄明白，再动手把第一个 React 项目跑起来。下一章再回来，正式把"小北的空间"重构成 React 版。

## 13.1 原生 JavaScript 写大应用，为什么会累

先回忆一下第 10 章我们是怎么让页面动起来的。想往待办清单里加一条，代码大概长这样：

```javascript
const li = document.createElement("li");
li.textContent = "背单词";
li.addEventListener("click", function () {
  li.classList.toggle("done");
});
document.querySelector("#todo-list").appendChild(li);
```

看出来了吗？原生 JS 写页面，是**一步一步指挥浏览器干活**：先找到位置，再创建元素，再填内容，再绑事件。这种写法有个行话叫"命令式"——你像个工头，站在旁边喊每一步口令。

页面小的时候没问题。可待办清单的功能一多，麻烦就来了：

- **数据和界面要手动保持一致**。待办存在一个数组变量里，页面上显示的是另一份。你改了数组，必须记得再去改页面；忘了任何一处，两边就对不上——小北遇到的"删了数据页面还留着"，就是这么来的。
- **同一件事要在好几个地方重复交代**。新增一条，要更新列表、更新计数、清空输入框；删除一条，又要再更新一遍列表和计数。功能越多，这种"别忘了顺手改一下"的地方就越多，漏一个就是一个 bug。
- **代码越长越没人敢动**。所有逻辑挤在一个文件里，你中有我、我中有你，改 A 处怕碰坏 B 处。

React 的解法是换一种思路，行话叫"声明式"：**你只负责描述"数据是这个样子的时候，页面应该长什么样"，剩下的事——具体改哪个元素、删哪一行——React 替你算好并动手。** 你从工头变成了设计师：只画图纸，不管施工。

数据变了，页面自动跟着变。仅凭这一点，前面那三类麻烦就消失了大半。接下来看看 React 具体是怎么组织页面的。

## 13.2 组件思维：页面是搭出来的

打开任何一个网站，你试着在心里给它画框框：最上面是导航栏，左边是菜单，右边是一张张卡片，卡片里又有小标题、图片和按钮。React 写页面，就是顺着这个思路来的：**把页面拆成一块块可以独立描述的零件，每块零件叫一个"组件"。**

组件说白了就是**一个 JavaScript 函数**，你把一段界面的长相交给它返回。比方说小北照片墙里的一张照片卡片，用组件写就是：

```jsx
function PhotoCard() {
  return (
    <div className="photo-card">
      <img src="sunset.jpg" alt="学校湖边的日落" />
      <p>学校湖边的日落</p>
    </div>
  );
}
```

（这段代码里一半像 HTML、一半像 JS，别慌，下一节专门讲它。）

页面就是组件一层层搭起来的：主页组件里放导航栏组件、照片墙组件；照片墙组件里放好多张照片卡片组件。就像搭积木——先做出小块，再拼成大块，最后拼成整页。

这样拆开有三个实实在在的好处：

- **能复用**。照片卡片写一次，墙上有多少张照片就用多少次，不用复制粘贴一堆 HTML。
- **改一处不牵全身**。导航栏的样式不对，只打开导航栏组件改，不用在长长的文件里大海捞针。
- **分工和排查都方便**。哪块显示不对，就去找哪个组件，责任田划分得很清楚。

记住这句话：**写 React，就是先想清楚"这个页面能拆成哪些组件"，再一个一个把组件写出来。** 这是和前面所有章节最不一样的地方。

## 13.3 JSX：长得像 HTML 的 JavaScript

上一节那段代码里，函数返回的东西长得几乎和 HTML 一模一样。它叫 **JSX**——一种让你直接在 JavaScript 里写"界面长相"的语法。你可以先把它理解成"React 专用版的 HTML"，写完之后构建工具（下一节要装的 Vite）会自动把它翻译成浏览器认识的普通 JavaScript，你不用操心翻译过程。

JSX 和 HTML 有九成像，但有三个区别是新手最常栽跟头的地方，必须先记住：

**区别一：`class` 要写成 `className`。** 因为 JSX 本质是 JavaScript，而 `class` 在 JS 里是保留词（第 9 章见过它亲戚）。所以给元素加类名要用 `className`：

```jsx
// HTML 里你熟悉的写法
<div class="card">照片</div>

// JSX 里必须这样写
<div className="card">照片</div>
```

**区别二：单个的标签也必须闭合。** HTML 里 `<img>`、`<br>` 单独出现没问题，JSX 里不行，必须在末尾加 `/>` 自我闭合：

```jsx
<img src="sunset.jpg" alt="日落" />
<br />
```

**区别三：大括号 `{}` 里可以放 JavaScript。** 这是 JSX 最有用的本事：在界面里挖个"窗口"，把变量的值直接显示出来：

```jsx
const name = "小北";
const photoCount = 12;

return <p>{name} 的相册里已经有 {photoCount} 张照片</p>;
```

页面上最终会显示"小北 的相册里已经有 12 张照片"。大括号里不光能放变量，还能放简单的计算，比如 `{photoCount + 1}`，甚至调用函数。回想 13.1 的痛点——"数据变了要手动同步到页面"，有了大括号，界面直接引用数据本身，数据一变，显示自然跟着变。

还有一条小规矩：**一个组件返回的 JSX 必须有一个最外层的包裹**，不能并排返回两个顶层标签。实在不想多套一层 `div`，可以用空标签 `<>...</>` 包起来。

## 13.4 props 与 state：组件的数据从哪来

组件要显示数据，数据从哪来？就两条路，名字分别叫 props 和 state，先各认识一下，本章只要求你分得清、用得上最基础的写法，第 14 章实战里会大量使用。

**props：父组件传给子组件的数据。** 回到照片卡片：墙上有十张卡片，长相一样，只是图片和标题不同。难道要写十个几乎一样的组件吗？不用——把不同的部分作为 props 传进去：

```jsx
function PhotoCard(props) {
  return (
    <div className="photo-card">
      <img src={props.img} alt={props.title} />
      <p>{props.title}</p>
    </div>
  );
}
```

使用的时候，像给 HTML 标签写属性一样把数据递过去：

```jsx
<PhotoCard img="sunset.jpg" title="学校湖边的日落" />
<PhotoCard img="cat.jpg" title="宿舍楼下的猫" />
```

一个组件，喂不同的数据，就显示出不同的卡片。注意：**props 是"别人给的"，子组件只能看不能改**，就像函数参数一样。

**state：组件自己保管的数据。** 有些数据是组件自己的小账本，比如计数器点了几次、待办清单里有哪几条。React 专门给了一个函数 `useState` 来保管这类数据：

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>你已经点了 {count} 次</p>
      <button onClick={() => setCount(count + 1)}>点我 +1</button>
    </div>
  );
}
```

慢慢拆解这段代码：`useState(0)` 的意思是"给我一份数据，初始值是 0"；它交回两个东西——`count` 是当前的值，`setCount` 是专门用来改这个值的函数。每次点按钮，就调用 `setCount(count + 1)` 把值加一；**值一变，React 立刻拿这个组件重新画一遍**，于是页面上的数字自己就更新了——你全程没有写一句"去把页面上的数字改掉"。

这就是 13.1 说的"声明式"落地的样子。一句话分清两者：**props 是从外面传进来的，state 是组件自己存、自己改的；想让界面跟着变的数据，就放进 state。**

## 13.5 用 Vite 搭起第一个 React 项目

道理讲完，动手。**Vite** 是目前最常用的前端项目脚手架工具（脚手架，就是帮你把项目骨架一键搭好的工具），React 官方也推荐用它起步。

先确认前置条件：第 2 章我们已经装好 Node.js，npm 随 Node.js 一起装好了。打开终端（Windows 在开始菜单搜"终端"或 PowerShell，Mac 打开"终端"应用），输入下面这条命令验证一下，能看到版本号（比如 v22.x）就说明没问题：

```bash
node -v
```

**第一步：创建项目。** 先进入你平时放代码的文件夹（第 2 章建的那个，比如 `code` 文件夹），然后运行：

```bash
npm create vite@latest xiaobei-react
```

`xiaobei-react` 是项目名，你也可以换成自己的。命令跑起来后会问你两个问题，用键盘方向键选择、回车确认：

- `Select a framework:` 选 **React**
- `Select a variant:` 选 **JavaScript**（先不用 TypeScript，那是进阶工具）

**第二步：安装依赖并启动。** 依次运行：

```bash
cd xiaobei-react
npm install
npm run dev
```

`npm install` 是把项目需要的工具包下载下来（第一次会慢一点，耐心等它跑完）。`npm run dev` 是启动开发服务器——终端会给你一个地址，通常是 `http://localhost:5173`。在浏览器打开它，你会看到 Vite 预置的欢迎页面：一个转圈的 React 标志和一个计数按钮。点一点按钮，数字会变——恭喜，你的第一个 React 程序已经跑起来了，而且你刚学的 `useState` 就藏在这个按钮里。想停下服务器，在终端按 `Ctrl + C`。

**第三步：逛一圈项目目录。** 用 VS Code 打开这个文件夹，重点认识三个文件：

- `index.html`：整个应用的入口页面，里面有个空的 `<div id="root">`，React 会把所有组件"挂"进这个 div 里。
- `src/main.jsx`：启动文件，负责把主组件渲染到上面那个 div 里，一般不用改。
- `src/App.jsx`：**主组件**，你刚才在浏览器里看到的欢迎页就是它画出来的。以后写 React，你的大部分时间都花在改 `App.jsx` 和它拆出来的各个组件上。

打开 `App.jsx` 对照着看：它就是一个名叫 `App` 的函数，返回了一大段 JSX——正是 13.2 和 13.3 讲的东西。试着把里面的标题文字改成"小北的第一个 React 页面"，保存，回到浏览器，页面会**自己刷新**成新样子（这个贴心功能叫热更新）。从这一刻起，你写页面的方式正式换代了。下一章，我们就用这套办法，把"小北的空间"整个搬进 React。

## 本章要点

- 原生 JS 写页面是"命令式"：手动指挥浏览器改 DOM，应用一大，数据和界面就容易对不上。
- React 是"声明式"：你只描述数据对应的界面长相，数据变了，React 自动更新页面。
- 组件就是返回界面长相的函数；写 React 先想"页面能拆成哪些组件"，再逐个实现。
- JSX 是在 JS 里写界面的语法，和 HTML 的三大区别：`className`、单标签要闭合、`{}` 里放 JS。
- 组件返回的 JSX 必须有最外层包裹，可以用 `<>...</>`。
- props 是父组件传给子组件的数据（只读）；state 是组件用 `useState` 自己保管的数据，改 state 会触发界面自动重画。
- 用 Vite 建 React 项目：`npm create vite@latest 项目名`，选 React + JavaScript，再 `npm install`、`npm run dev`。

## 动手 Kata

1. **把项目跑起来**：按 13.5 的步骤，用 Vite 创建一个名为 `my-first-react` 的项目并启动。做完应该看到：浏览器打开 `http://localhost:5173`，出现 Vite 欢迎页，点击计数按钮数字会增加。
2. **改主组件**：打开 `src/App.jsx`，把页面上的标题文字改成你的名字加"的主页"，段落改成一句自我介绍，保存。做完应该看到：浏览器页面自动刷新成你改的样子，不需要手动刷新。
3. **写你的第一个组件**：在 `App.jsx` 里新写一个 `PhotoCard` 组件（照 13.2 的例子），在 `App` 组件里用两次，分别通过 props 传入不同的图片地址和标题（图片可以用第 4 章主页里用过的那几张）。做完应该看到：页面上出现两张长相相同、内容不同的照片卡片。
4. **做一个计数器**：新写一个 `Counter` 组件放进页面，按 13.4 的例子用 `useState` 实现"点一次加一"，再自己加一个"归零"按钮。做完应该看到：点 `+1` 数字变大，点"归零"回到 0，全程不刷新页面。

## 翻车现场

小北第一次自己写 JSX，把第 7 章 CSS 里用惯的写法原样搬了过来：

```jsx
<div class="photo-card">
  <img src="sunset.jpg">
  <p>学校湖边的日落</p>
</div>
```

保存之后，页面直接白屏，浏览器控制台（按 F12 打开）里躺着两条刺眼的红字。一条是警告：`Warning: Invalid DOM property 'class'. Did you mean 'className'?`——React 在提醒他，JSX 里的类名要写 `className`。另一条更严重，是直接让页面崩掉的报错：`Unterminated JSX contents`，意思是"JSX 标签没写完"。他盯着代码看了半天才发现：`<img>` 后面少了那个 `/`。

这两个坑，几乎每个 React 新手都会各踩一遍，报错信息其实都把答案写在脸上了。改法就是 13.3 的三条规矩：类名写 `className`；`<img>`、`<br>` 这类单标签末尾加 `/>`。记住：**白屏先别慌，打开控制台看红字，它通常直接告诉你错在哪一行、错在哪。**
